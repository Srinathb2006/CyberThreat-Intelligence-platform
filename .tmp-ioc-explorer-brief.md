# IOC Explorer design brief

Implement the standalone `/ioc-explorer` frontend page in the existing React application. The page is for authenticated analysts investigating the application’s persisted APK IOC database.

Use the existing dark analyst workspace, typography, compact panels, table, modal, badges, and filter controls. The visual focus is a dense evidence table with a narrow filter strip and an explicit match-state column. No images or external assets are needed.

The backend API is `GET /api/ioc-explorer` with optional `search`, `type`, `severity`, `confidence`, and `scanId` query parameters; and `GET /api/ioc-explorer/{iocId}`. It returns only the current user’s real extracted IOC records. Response rows and detail results include IOC fields plus `scanId`, `scanTarget`, and `threatMatches`, where every match has status/matchType/severity/confidence/matchedAt/description and optional threat intelligence fields. Do not call static analysis extraction or threat correlation endpoints. No sample data.

Provide text search, type/severity/confidence/scan filters, reset and refresh, loading/error/empty states, pagination if needed, a clickable row that opens full IOC details and threat-match information, and clear wording for unmatched and review/no-match records. All IOC strings and descriptions must render as inert escaped text: do not turn URLs into links and do not fetch them.

Use an API module under `frontend/src/api`. Connect `/ioc-explorer` directly in `App.jsx`, excluding it from `ModulePage`’s placeholder routing. Preserve existing URL Scanner and Phishing pages. Add meaningful frontend tests with the current test stack. Build and run tests; all commands should use the `rtk` prefix.
